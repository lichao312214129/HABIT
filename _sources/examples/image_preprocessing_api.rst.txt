Image preprocessing API (batch + atomic)
========================================

Public symbols (registered in ``habit.api.registry``):

* :func:`~habit.run_preprocess` / recipe :func:`~habit.recipes.preprocess_images`
  — **batch** directory pipeline (``data_dir`` → ``processed_images/``).
* :func:`~habit.preprocess_subject` — **atomic** subject-level operator
  (``Subject`` in → ``Subject`` out; no YAML, no filesystem).
* :func:`~habit.preprocess_image` — **atomic** single-volume operator
  (:class:`~habit.api.image.ImageVolume` in → ``ImageVolume`` out).

The atomic surfaces satisfy the embedding red line: a third-party notebook
can call ``preprocess_subject(cohort[0], steps)`` on one failing case without
accepting HABIT's directory conventions.

Steps use the same ordered mapping shape as the YAML ``preprocessing:``
block (``resample``, ``zscore_normalization``, ``n4_correction``, …).

Atomic steps (copy, swap DATA)
------------------------------

Each registered preprocessor is one mapping key. The snippets below use
:func:`~habit.preprocess_subject` / :func:`~habit.preprocess_image` on a
subject you already loaded (``demo_data/preprocessed`` or synthetic).
Full runnable generator:
``docs/source/examples/scripts/image_preprocessing_steps_demo.py``.
YAML field reference: :doc:`../configuration/preprocessing`.

Change ``DATA`` / ``MODALITIES`` / ``ROI`` in that script to your tree.
``dcm2nii`` is a **file** converter (CLI), not an in-memory volume operator
— see :doc:`../how_to/preprocess`.

**Resample** (target spacing in mm; masks use nearest neighbour)::

   from habit import preprocess_image

   out = preprocess_image(
       subject.image("T1"),
       {"resample": {"target_spacing": [1.0, 1.0, 1.0], "img_mode": "bilinear"}},
       mask=subject.mask("tumor"),
       modality="T1",
   )

.. figure:: ../_static/images/examples/preprocess_resample.png
   :alt: Resampled intensity volume
   :width: 520

   Resample to 2 mm isotropic (synthetic or demo subject).

**Z-score** (per-volume intensity; optional ROI stats and clip)::

   from habit import preprocess_subject

   out = preprocess_subject(
       subject,
       {"zscore_normalization": {"only_inmask": True, "mask_key": "tumor", "clip_values": [-3, 3]}},
   )

.. figure:: ../_static/images/examples/preprocess_zscore.png
   :alt: Anatomy beside z-scored intensity
   :width: 720

   Z-score inside the ROI, clipped to :math:`[-3, 3]`.

**N4 bias-field correction** (SimpleITK N4)::

   out = preprocess_subject(subject, {"n4_correction": {"num_fitting_levels": 4}})

.. figure:: ../_static/images/examples/preprocess_n4.png
   :alt: Anatomy beside N4-corrected intensity
   :width: 720

   N4 correction. On a nearly flat synthetic volume the visual change can
   be small; on MRI with a real bias field it is the intensity-homogeneity
   step of the literature chain (N4 → register → resample → z-score).

**Histogram standardization** (Nyúl landmarks → ``[target_min, target_max]``)::

   out = preprocess_subject(
       subject,
       {"histogram_standardization": {"target_min": 0.0, "target_max": 100.0}},
   )

.. figure:: ../_static/images/examples/preprocess_histogram.png
   :alt: Histogram-standardized intensity
   :width: 720

   Percentile landmarks mapped to 0–100.

**Adaptive histogram equalization**::

   out = preprocess_subject(
       subject,
       {"adaptive_histogram_equalization": {"alpha": 0.3, "beta": 0.3, "radius": 5}},
   )

.. figure:: ../_static/images/examples/preprocess_clahe.png
   :alt: Adaptive histogram equalization
   :width: 720

   Local contrast (CLAHE-style). Use when the scientific question needs
   local contrast, not when you still need quantitative MRI units.

**Reorientation** (canonical axis code; ``closest`` = flip/permute only)::

   out = preprocess_subject(
       subject,
       {"reorientation": {"target_orientation": "RAS", "mode": "closest"}},
   )

.. figure:: ../_static/images/examples/preprocess_reorient.png
   :alt: Volume after RAS reorientation
   :width: 520

   Reorient to RAS. ``strict`` additionally resamples; ``closest`` does not
   interpolate intensities.

**Registration** (SimpleITK affine here; ANTs SyN needs ``habit[registration]``)::

   out = preprocess_subject(
       subject,
       {
           "registration": {
               "fixed_image": "T1",
               "backend": "simpleitk",
               "type_of_transform": "Affine",
           }
       },
   )

.. figure:: ../_static/images/examples/preprocess_register.png
   :alt: After SimpleITK affine registration
   :width: 720

   Affine registration onto the fixed modality. Multi-modal MRI in the
   bundled demo is often already on one grid; the call is still the
   embedding-API shape. Deformable SyN: ``backend='ants'`` after
   ``pip install habit[registration]``.

These image steps are **not** the clustering-time
``winsorize`` / ``minmax`` chain. Mixing the two silently changes the
habitat definition — see :doc:`habitat_preprocessing`.
