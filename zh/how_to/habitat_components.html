Habitat Spec 组件目录#

已注册 Spec 名称的 参考 选择器。演练留在生境指南（Examples ）。本页列出每个内置名称、构造参数及 Python / YAML 对应。

Concept and embedding: 入门教程 · 由原子组件构建两步法生境.

Gallery 脚本（一步法、两步法、direct-pooling）展示 一个 完整 HabitatSpec 。本页从该示例向外选择：各阶段有哪些注册名、各参数含义，以及如何在 Python 与 YAML 中写相同选择。

When a recipe shows Spec("raw") or Spec("kmeans"), look up that stage below. Parameter tables are generated at Sphinx build time from each component constructor. Do not copy them into notebooks — look names and constructor signatures up at runtime:

from habit.plugins import list_plugins
from habit.spec import parse_feature_expression
from habit.voxel_features import RawVoxelFeatures, VoxelFeatureExtractorRegistry

print([info.name for info in list_plugins("voxel_feature_extractor")])
print(VoxelFeatureExtractorRegistry.constructor_signature("raw"))
voxel = VoxelFeatureExtractorRegistry.create("raw", modality="T1")
voxel = RawVoxelFeatures(modality="T1")

完整实时目录（每个领域）：插件 introspection API 。

HabitatSpec 的组装方法#

生境研究是 有序阶段列表 。每个 Stage 为标签加 Spec 。叶节点为单序列上单提取器（第 1A 节）。组合序列或族为由 parse_feature_expression() 构成的树（第 1B 节）:

Stage("<label>", Spec("<registered name>", {<params>}))
Stage("<label>", parse_feature_expression('concat(raw("T1"), voxel_radiomics("T2"))'))

Stage labels (extract_voxel_features, quantify2, …) are not role keywords. HABIT infers the scientific role from position + the component's registry domain. Recommended labels:

策略由序列推断：

  • two_step — partition + pool

  • direct_pooling — 仅 pool （无 partition）

  • one_step — 无 partition 与 pool（逐受试者生境）

kmeans and gmm exist in two domains (超体素izer and 生境-model fitter). Place them before pool to partition, or immediately before assign to fit 生境.

Python 与 YAML 为同一文档#

Spec.to_dict() 即 YAML 组件块。v1 生境文档在 spec: 下存相同映射。

from habit.spec import HabitatSpec, Spec, Stage

spec = HabitatSpec(
    name="habitat_one_step",
    stages=(
        Stage("extract_voxel_features", Spec("raw", {"modalities": ["LAP"]})),
        Stage("fit", Spec("kmeans", {"min_habitats": 2, "max_habitats": 10, "validation": "elbow"})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
    ),
    random_seed=42,
)

等效 v1 YAML (stages 表单):

spec:
  name: habitat_one_step
  random_seed: 42
  stages:
    - name: extract_voxel_features
      component:
        name: raw
        params:
          modalities: [LAP]
    - name: fit
      component:
        name: kmeans
        params:
          min_habitats: 2
          max_habitats: 10
          validation: elbow
    - name: assign
      component:
        name: nearest_centroid
        params: {}
    - name: quantify
      component:
        name: volume
        params: {}

具名字段构造函数（ voxel_feature_extractor: 、 habitat_model_fitter: 、…）已弃用：仍可加载并保留历史指纹，但新 Python 与 YAML 应仅用 stages 。见 Spec、RunPolicy 和 YAML 同构 与 生境分割配置 。

1. 体素特征提取#

Required. Turns each 受试者's images + ROI into a per-体素 特征 field. First pick one extractor on one series (a leaf). Only then compose several series or families with a combiner. A longer modalities list is not a substitute for mixing families.

A. 单模态体素提取#

一法、一序列、一列（或一块列）。无 concat 。表达式形式引号模态； Spec 形式用 modality=:

from habit.spec import parse_feature_expression

Stage("extract_voxel_features", Spec("raw", {"modality": "T1"}))
Stage(
    "extract_voxel_features",
    parse_feature_expression('raw("T1")'),
)
Stage(
    "extract_voxel_features",
    parse_feature_expression('local_entropy("T1", kernel_size=3, bins=32)'),
)
Stage(
    "extract_voxel_features",
    parse_feature_expression('voxel_radiomics("T2", kernel_radius=3)'),
)

YAML:

- name: extract_voxel_features
  component:
    name: raw
    params:
      modality: T1

voxel_radiomics 需要 pyradiomics extra，比 raw / local_entropy 慢得多。矩阵构建可用 HABIT GPU 路径（ use_gpu_matrices ）替代 PyRadiomics C 扩展；见 体素纹理特征图 。

B. 多模态体素组合#

组合器在相同体素（相同 ROI）上连接 已提取 的叶节点。两种写法 — 表达式字符串或嵌套 children — 共享同一指纹。表达式中的模态须 加引号 。

同族多序列。 叶节点仍接受模态列表（ raw("T1", "T2") 或 modalities: [T1, T2] ）。两 concat 叶的 raw 是同一思想的树写法:

Stage("extract_voxel_features", Spec("raw", {"modalities": ["T1", "T2"]}))
Stage(
    "extract_voxel_features",
    parse_feature_expression('concat(raw("T1"), raw("T2"))'),
)

YAML:

- name: extract_voxel_features
  component:
    name: raw
    params:
      modalities: [T1, T2]

不同特征族。 Texture on T2, intensity on T1 — this needs a tree, not a longer modalities list:

Stage(
    "extract_voxel_features",
    parse_feature_expression(
        'concat(raw("T1"), voxel_radiomics("T2", kernel_radius=3))'
    ),
)
Stage(
    "extract_voxel_features",
    parse_feature_expression(
        'concat(local_entropy("T1", kernel_size=3, bins=32), raw("T2"))'
    ),
)

第一棵树的结构化形式（同一 Spec）:

Stage(
    "extract_voxel_features",
    Spec(
        "concat",
        {
            "children": [
                {"name": "raw", "params": {"modality": "T1"}},
                {
                    "name": "voxel_radiomics",
                    "params": {"modality": "T2", "kernel_radius": 3},
                },
            ],
        },
    ),
)

YAML（表达式 — 最短）:

- name: extract_voxel_features
  component: 'concat(raw("T1"), voxel_radiomics("T2", kernel_radius=3))'

YAML（结构化）:

- name: extract_voxel_features
  component:
    name: concat
    params:
      children:
        - name: raw
          params: {modality: T1}
        - name: voxel_radiomics
          params: {modality: T2, kernel_radius: 3}

导出通道 — 各一个 combiner。 本页勿在一个表达式中嵌套 ratio 、 weighted_concat 与纹理叶。 as_="label" 重命名 单列 节点以免两分支冲突:

Stage(
    "extract_voxel_features",
    parse_feature_expression(
        'ratio(raw("T1"), raw("T2"), as_="t1_over_t2")'
    ),
)
Stage(
    "extract_voxel_features",
    parse_feature_expression(
        'weighted_concat(raw("T1", as_="t1w"), raw("T2", as_="t2w"), weights=[2.0, 1.0])'
    ),
)

内置： concat 、 weighted_concat （ weights=[...] ）、 average 、 ratio 、 difference 、 kinetic 、 expression 。语法（严格；坏输入拒绝不猜）：模态加引号（ raw("T1") ）；参数 key=value ；子项中引号字符串为隐式 raw 。裸 raw(T1) 仅 v0.1。

嵌套树与列名：将自定义特征提取器作为插件 。combiner 之外运算：将自定义特征提取器作为插件 （ expression 或自定义插件）。

2. 特征预处理#

可选、可重复。 Same method names before and after pool. Before partition / fit they scale the units that 聚类 sees; after pool they are 队列-level and travel with HabitatModel.

典型体素级链： winsorize 然后 minmax 。两步法 / 直接池化运行勿跳过缩放 — 见 受试者级预处理 。

Python:

Stage("preprocess1", Spec("winsorize", {"winsor_limits": (0.05, 0.05), "across_features": False}))
Stage("preprocess2", Spec("minmax", {"across_features": False}))

YAML:

- name: preprocess1
  component:
    name: winsorize
    params:
      winsor_limits: [0.05, 0.05]
      across_features: false
- name: preprocess2
  component:
    name: minmax
    params:
      across_features: false

6. 适合的栖息地#

Required. 内置名： kmeans 、 gmm 、 consensus 。学习质心（有 pool 为队列级；否则逐受试者）。

consensus 运行销售的 InMoose / Sajovic 共识聚类 (GPL-3.0 或更高版本 ，而非 Apache-2.0；参见 NOTICE 和 habit/third_party/inmoose/LICENSE) 对合并的条目进行处理，然后将每个共识组的特征向量均值存储为质心。它适用于超级体素或受试者，而非体素级矩阵。已验证的图形：生境共识聚类 。参数： n_habitats 、 min_habitats 、 max_habitats 、 n_resamples （默认 50）、 resample_proportion （默认 0.5）、 inner （ kmeans 或 agglomerative ）、 n_init 、 max_iter 、 max_items 。 bestK 遵循销售的 CDF 面积规则，从不自行成为 max_habitats 。

kmeans 与 gmm 共享参数： n_habitats 、 min_habitats 、 max_habitats 、 validation 、 n_init 、 max_iter 。 gmm 另有 covariance_type （ full / tied / diag / spherical ）。 consensus 无 validation ；用 vendored delta(k) 规则选 K。

省略 n_habitats （或传 None ）以在 min_habitats..max_habitats 上由 validation 选 K。无 "auto" 字符串。

允许的 validation 值：

  • kmeans — elbow （默认； kneedle 别名）、 kneedle 、 inertia 、 silhouette 、 calinski_harabasz 、 davies_bouldin 、 gap 。列表中每项投一票。HABIT elbow / kneedle 为 inertia 上 Kneedle（Satopaa 等，2011），非文献非正式 elbow（Thorndike，1953）亦非 pre-v1.0 离散曲率二阶差规则 — 见 构建生境图 。

  • gmm — bic （默认）、 aic 、 davies_bouldin （最小化）； silhouette 、 calinski_harabasz 、 gap （最大化）； bic_elbow （Prior 2024 BIC 斜率规则）。
