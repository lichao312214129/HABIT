生境分割配置#

生境分析配置参数#

This section covers habitat analysis configuration. CLI: habit get-habitat -c <yaml>. Demo training: config/habitat/config_habitat_two_step.yaml; prediction: config/habitat/config_habitat_two_step_predict.yaml; SLIC supervoxel example: config/habitat/config_habitat_two_step_supervoxel_slic.yaml (parameter details in "habitat_segmentation.supervoxel — SLIC Superpixel Configuration" below).

示例配置文件：

run_mode: train
pipeline_path: ./results/habitat_pipeline.pkl
data_dir: ./file_habitat.yaml
out_dir: ./results/habitat/train

feature_construction:
  voxel_level:
    method: concat(raw(pre_contrast), raw(LAP), raw(PVP), raw(delay_3min))

  supervoxel_level:
    supervoxel_file_keyword: '*_supervoxel.nrrd'
    method: mean_voxel_features()

  preprocessing_for_subject_level:
    methods:
      - method: winsorize
        winsor_limits: [0.05, 0.05]
        global_normalize: true
      - method: minmax
        global_normalize: true

  preprocessing_for_group_level:
    methods:
      - method: binning
        n_bins: 10
        bin_strategy: uniform
        global_normalize: false

habitat_segmentation:
  clustering_mode: two_step

  supervoxel:
    algorithm: kmeans
    n_clusters: 50
    random_state: 42
    max_iter: 300
    n_init: 10

  habitat:
    algorithm: kmeans
    min_clusters: 2
    max_clusters: 10
    habitat_cluster_selection_method: elbow
    fixed_n_clusters: null
    random_state: 42
    max_iter: 300
    n_init: 10

processes: 2
cap_processes_to_gpu_pool: false
individual_subject_timeout_sec: 900
individual_subject_spawn_timeout_sec: 120
individual_subject_graceful_shutdown_sec: 15
on_subject_failure: continue
oom_backoff: true
oom_reduce_workers_by: 1
resume: true
strict_checkpoint_hash: false
checkpoint_dir: null
force_rerun_subjects: []
retry_failed_subjects: false
individual_subject_auto_retry_rounds: 2
individual_subject_parallel_mode: persistent
persistent_worker_max_consecutive_failures: 1
persistent_worker_recycle_after_tasks: 0
clear_checkpoint_on_success: false
plot_curves: true
save_images: true
save_results_csv: true
random_state: 42
verbose: true
debug: false

run_mode ：运行模式

  • Type ：string

  • Required ：否

  • 默认 ： train

  • Allowed values ： train 、 predict

  • Description ： train 训练新模型； predict 用预训练流水线推理。

  • 示例 ： train

pipeline_path ：流水线文件路径

  • Type ：string

  • 必需 ：否（ predict 模式下必需）

  • 默认 ： null

  • Description ：已训练 pipeline 文件路径。

  • 示例 ： ./results/habitat_pipeline.pkl

data_dir/out_dir （生境分析顶层）

  • Type ：string

  • Required ：yes

  • Default ：无（必填）

  • Description: data_dir may be a directory or a manifest YAML (e.g. file_habitat.yaml, or file_habitat_registered_single_roi.yaml when modalities are already co-registered and each subject has one ROI). Never a bare .nii.gz. out_dir is the default parent directory for results and checkpoints. See 图像操作.

feature_construction ：特征提取设置

  • 类型 ：object

  • 必填 ：在 train 中为必填；在 predict 中可省略

  • 默认 ： null

  • 说明 ：未设置时验证拒绝配置或按运行模式报错。子块 voxel_level / supervoxel_level / preprocessing_* 见下文。

本工作流 YAML 字段命名 （避免混淆 method / methods / algorithm ）：

  • feature_construction.*.method （单数）：一条 函数表达式 字符串（ concat(voxel_radiomics(T2)) ）。

  • preprocessing_for_* .methods (plural): an ordered list of preprocessing steps; each item has its own method: winsorize step type.

  • habitat_segmentation.supervoxel.algorithm ：超体素划分算法（ slic 、 kmeans 、 gmm ）。

  • habitat_segmentation.habitat.algorithm ：队列生境模型拟合器（ kmeans 、 gmm ）。

  • habitat_cluster_selection_method / selection_method ：聚类数量验证指标（ elbow 、 silhouette ，…）。

voxel_level ：体素级特征提取

  • method ：特征提取方法 expression

    • Type ：string

    • Required ：yes

    • Default ：无（必填）

    • Description ：支持函数式语法组合多个提取器。

    • Expression conventions （ voxel_level / supervoxel_level 共用）：

      • 按模态提取时（ raw 、 voxel_radiomics 、 supervoxel_radiomics 等）， 即使单模态 也须用 concat(...) 等外层 combiner 包裹；内层表达式为每模态子表达式；外层跨模态合并结果。

      • 括号内逗号分隔 token 为 参数名占位符 或 图像模态名 （匹配 images/<subject>/<modality>/ 子目录）， 非 Python 关键字参数；实际路径与数值放在兄弟 params dict。

      • 绑定规则 ：参数仅当其名出现在 F 括号内才绑定到函数 F(...) （模态名除外）。 params 中未出现在任何函数括号内的键会触发弃用警告。

      • Defaults: optional parameters omitted from both parentheses and params receive built-in defaults from each method's method_param_spec (see extractor classes under habit/compat/engines/habitat_analysis/clustering_features/).

      • **Bundled params_file ** ： voxel_radiomics / supervoxel_radiomics 的 params_file 可选。省略时 HABIT 使用 habit/resources/radiomics/ 内置预设（CT R3B12 体素预设；超体素全集预设）。运行时记录解析后的绝对路径。

      • 推荐最简形式： concat(voxel_radiomics(T2)) 与 params: {} — 使用捆绑 CT R3B12 params_file 、 kernel_radius: 3 、 voxel_batch: 1000 、 use_torch_radiomics: auto 。仅覆盖时在括号中列名（如 concat(voxel_radiomics(T2, kernel_radius)) 与 kernel_radius: 1 用于 MRI）。

      • 严格引号形式（v1 特征树） ： when the expression contains quoted 模态 strings, it is parsed by the strict v1 parser (parse_feature_expression()) into a 特征 Spec tree instead of the permissive v0.1 mini-language. Rules: 模态 are quoted (raw("T1")), parameters are explicit key=value (local_entropy("T2", kernel_size=5)), combiner children are nested calls (a bare quoted string among children is an implicit raw leaf), and as_="label" renames a single-column node's output. Ambiguous input fails loudly instead of being guessed. Available combiners: concat, weighted_concat (weights=[...]), average, ratio / difference (two children), kinetic, expression. Example: concat(raw("LAP"), ratio(raw("LAP"), raw("PVP"), as_="lap_over_pvp")).

  • params ：体素级提取器参数字典

    • 类型 ：字典

    • Required ：否

    • Default: {}

    • 说明 ：传给 method 所引用提取器的键值对（例如 params_file 的 voxel_radiomics 可能位于 params ，取决于解析器行为）。无额外参数时可省略整个 params 块（默认为空 dict）。

    • 可用的方法和参数 ：

raw(image_name):

  • Description: Extract raw image 体素 values (most basic 特征)

  • Parameters ：无

  • Example ： raw(LAP)

concat(...):

  • Description ：拼接多个特征向量

  • Parameters ：接受多个特征提取表达式

  • Example ： concat(raw(pre_contrast), raw(LAP), raw(PVP), raw(delay_3min))

kinetic(...):

  • 描述 ：提取动力学特征（注入/洗出斜率等）

  • Parameters:

    • timestamps （str，required）：时间戳文件路径

    • 接受多个 raw(image_name) 表达式

  • Example ： kinetic(raw(LAP), raw(PVP), raw(delay_3min), timestamps=...)

  • Extracted features ：

    • wash_in_slope ：wash-in 斜率

    • wash_out_slope_lap_pvp ：LAP 到 PVP 廓清斜率

    • wash_out_slope_pvp_dp ：PVP 至延迟期洗出斜率

local_entropy(...):

  • Description ：计算局部熵（局部纹理复杂度）

  • Parameters:

    • kernel_size （整数，默认值： 3 ）：本地邻域大小

    • bins （int，默认 32 ）：直方图 bin 数

  • Example ： local_entropy(raw(LAP), kernel_size=5, bins=32)

voxel_radiomics(...):

  • Description ：提取体素级放射组学特征

  • Parameters:

    • params_file （str，可选）：PyRadiomics 参数文件路径；省略则用 bundled CT R3B12 预设

    • kernel_radius （int，默认 CT R3B12 捆绑预设 3 ； 1 = 3×3×3， 3 = 7×7×7）：局部邻域半径

    • voxel_batch （int，默认 1000 ）：体素 batch； -1 一次处理全部 ROI 体素（原生 PyRadiomics，无 batch）。正值限内存（GPU 或大 ROI 建议 512 – 1000 ）

    • use_torch_radiomics （str，默认 auto ）： auto 在已装 torch 且 CUDA 可用时用 TorchRadiomics，否则 CPU PyRadiomics； true 强制 torch； false 始终 CPU

    • use_gpu_matrices (str, default: auto): when Torch放射组学 is on, auto builds GLCM/GLDM/GLRLM/GLSZM/NGTDM on GPU (habit.kernels.radiomics.gpumatrices); false keeps the Py放射组学 cMatrices C extension (same counts). Upstream pytorch放射组学 always uses C for this step. See 体素纹理特征图.

    • class_progress （bool，默认 false ）： true 时对每个 PyRadiomics 类（firstorder、glcm 等）打印并 tqdm。默认安静； Cohort.map 仍报告受试者。

    • torch_device （str，default： auto ）： torch_gpus 未设时的单 GPU 设备

    • torch_gpus （list/int/str）：允许的 GPU 索引，如 [0, 1, 2] 或 "0,1,2" ；设置时覆盖 torch_device

    • torch_gpu_count （int，optional）：使用 torch_gpus 中前 N 个 GPU

    • torch_dtype （str，默认 float32 ）：Torch 计算 dtype（ float32 或 float64 ； float64 更接近 CPU PyRadiomics）

  • Voxel GLCM note: Use config/radiomics/params_voxel_radiomics.yaml (explicit list of 21 stable GLCM features). If params_file lists only glcm: without feature names, PyRadiomics computes all 24 GLCM features; in small neighborhoods with many uniform voxels, GLCM degenerates to 1×1 matrices and MCC / Imc1 / Imc2 feature values or mutual information can crash or produce NaN on CUDA/MKL. HABIT auto-replaces with the 21 stable features and logs a warning when GLCM is unrestricted; if features are explicitly listed in params_file, user configuration is respected.

  • CT voxel texture (R3B12): Literature recommends kernel_radius: 3 and binWidth: 12 HU (R3B12 configuration; better repeatability and robustness to kernel/binning than R1B25). Omit params_file to use bundled params_voxel_radiomics.yaml; kernel_radius defaults to 3. Reference: Prior O, et al. Radiol Artif Intell. 2024;6(2):e230118. https://doi.org/10.1148/ryai.230118 The simulated-retest perturbation used to define those precise features is prior2024_retest_perturbation() (MIRP 1.2.0 Appendix S2: noise + 0.5-voxel translation fraction + 0.5° z-rotation). See 在扰动下精确特征与所有纹理.

  • Example ： concat(voxel_radiomics(T2)) 且 params: {} （CT R3B12 默认）；覆盖示例： concat(voxel_radiomics(T2, kernel_radius)) 且在 kernel_radius: 1 中 params

  • Full examples ：

    # Simple concatenation of raw images
voxel_level:
  method: concat(raw(pre_contrast), raw(LAP), raw(PVP), raw(delay_3min))

# Kinetic features
voxel_level:
  method: kinetic(raw(LAP), raw(PVP), raw(delay_3min))
  params:
    timestamps: ./timestamps.txt

# Combine local entropy and raw values
voxel_level:
  method: concat(raw(LAP), local_entropy(raw(LAP)))
  params:
    kernel_size: 5
    bins: 32

# Voxel-level radiomics (texture features, slower; single modality still needs concat)
voxel_level:
  method: concat(voxel_radiomics(T2))
  params: {}

  • params ：全局参数

    • 类型 ：字典

    • Required ：否

    • Default: {}

    • Description ：所有提取器共享参数。 voxel_radiomics 专用键（ voxel_batch 、 use_torch_radiomics 等）属于 params ， 不必 出现在 method 表达式字符串；表达式未列出的键自动合并转发。

    • Common parameters ：

      • timestamps （str）：时间戳文件路径（用于 kinetic）

      • kernel_size （int）：局部邻域大小（local_entropy）

      • bins （int）：直方图 bin 数（用于 local_entropy）

      • params_file （str）：PyRadiomics 参数文件（用于 voxel_radiomics）

      • kernel_radius (int): 体素 放射组学 neighborhood radius (for 体素_放射组学)

      • voxel_batch （int）：体素放射组学批大小（用于 voxel_radiomics；默认 1000 ； -1 = 不分批）

      • use_torch_radiomics （str）：TorchRadiomics 加速（ auto / true / false ）

      • use_gpu_matrices （str）：GPU 纹理矩阵后端（ auto / true / false ）；见 体素纹理特征图

      • class_progress （bool）：逐类体素放射组学 tqdm（默认 false ）

      • torch_device （str）：单 GPU 设备（未设 torch_gpus 时）

      • torch_gpus （列表/整数/字符串）：允许的 GPU 列表

      • torch_gpu_count （int）：实际使用 GPU 上限

      • torch_dtype (str): Torch dtype (体素_放射组学 torch backend)

supervoxel_level ：超像素级特征提取（可选）

  • Block default ： null （省略 = 无超体素块； two_step 训练通常需要）

  • supervoxel_file_keyword ：超像素文件 glob 模式

    • Type ：string

    • Required ：否（已配置 supervoxel_level 时）

    • Default: *_supervoxel.nrrd

    • 说明 ： Matches existing 超体素 segmentation files (from two_step mode).

    • Example: "*_supervoxel.nrrd"

  • method ：特征聚合/提取方法

    • Type ：string

    • 必需 ：否（配置 supervoxel_level 时推荐）

    • Default ： mean_voxel_features()

    • Description: Defines how 体素 特征 aggregate to 超体素, or direct 超体素 extraction. For multi-模态 extractors such as supervoxel_radiomics, expression conventions match voxel_level (single 模态 still needs outer concat(...) etc.; see "Expression conventions" above).

    • 可用的方法和参数 ：

mean_voxel_features():

  • Description ：各超体素内体素特征均值（最常见）

  • Parameters ：无

  • Use case ：将体素级特征（来自 voxel_level ）聚合到超体素级

  • Example ： mean_voxel_features()

mean("<modality>") / std("<modality>") / percentile("<modality>", q=...) （仅严格引号形式）：

  • 说明 ： Single-模态 region statistics — aggregate one 模态's 体素 image signal (not the voxel_level 特征) per 超体素: mean, standard deviation, or the q -th percentile

  • Parameters ： q （int/float，仅 percentile）； source: "working" | "original" 选择预/后预处理信号； as_="label" 重命名输出列

  • 用例 ：用组合器组合逐模态统计，例如 concat(mean("T1"), std("T1", as_="t1_spread"), percentile("T2", q=90))

concat(supervoxel_radiomics(<modality>, params_file), ...) ：

  • Description ：每超体素标签提取 全 ROI 放射组学纹理（非体素核邻域）。须放在 concat(...) （或另一外层 combiner）内；单模态示例： concat(supervoxel_radiomics(T2, params_file)) 。

  • Discretization ：默认 per-label binWidth （ union_bin=false ），对齐 PyRadiomics execute() 。 union_bin=true 时在并集掩膜（ sv_map > 0 ）上共用分箱，再 per-label 提取

  • Matrix backend ： use_supervoxel_cext 默认 auto ：编译 supervoxel_cext 时用 C 扩展 batch 矩阵（ pip install -e . ）；否则回退 Torch/PyRadiomics 堆叠矩阵。 false 强制 Torch/PyRadiomics（ matrix_backend=torch_cmatrices ）即使存在 C 扩展

  • Feature backend ： use_torch_radiomics 解析为 torch 时用 TorchRadiomics（GPU/CPU torch）；否则 CPU PyRadiomics（语义相同）

  • 参数 （在 feature_construction.supervoxel_level.params ；可继承 voxel_level.params 的 torch 键）：

    • params_file （str，optional）：PyRadiomics 参数 YAML；省略则用 bundled 全集预设

    • supervoxel_batch (int): batch group size, default 64 (not kernel radius)

    • supervoxel_union_bbox_crop （bool）：裁剪到并集 bbox，默认 true

    • union_bin （bool）：逐标签 bin（默认 false ， execute() 科学）或单一 union 掩膜 bin（ true ）

    • use_supervoxel_cext (str | bool): auto / true / false, default auto; must be in supervoxel_level.params (not in params_file)

    • use_torch_radiomics （str）： auto / true / false

    • torch_gpus / torch_gpu_count / torch_device / torch_dtype ：与体素级相同

  • 注意 ： kernel_radius 仅用于 voxel_radiomics ； supervoxel_radiomics 不使用

  • Use case ：不经 voxel_level 特征，直接从超体素区域做纹理放射组学

  • Example: concat(supervoxel_radiomics(T2)) with params: {} (bundled preset)

  • Method comparison ：

    • mean_voxel_features() ：依赖 voxel_level 特征；快；适合多数情况

    • concat(supervoxel_radiomics(...), ...) ：独立 ROI 放射组学；默认 per-label bin 对齐 execute() ；设 union_bin=true 跨超体素共享灰度

  • Full examples ：

    # Scenario 1: aggregate voxel features (recommended)
supervoxel_level:
  supervoxel_file_keyword: '*_supervoxel.nrrd'
  method: mean_voxel_features()

# Scenario 2: direct radiomics (single modality still needs concat; replace T2 with modality under data_dir)
supervoxel_level:
  supervoxel_file_keyword: '*_supervoxel.nrrd'
  method: concat(supervoxel_radiomics(T2))
  params: {}

# Scenario 2b: multi-modality supervoxel radiomics
supervoxel_level:
  supervoxel_file_keyword: '*_supervoxel.nrrd'
  method: concat(
    supervoxel_radiomics(T1),
    supervoxel_radiomics(T2))
  params: {}

  • params: Parameters

    • 类型 ：字典

    • Required ：否

    • Default: {}

    • Description ：提取器参数。无参方法如 params 可省略 mean_voxel_features() 。常见 supervoxel_radiomics 键： params_file 、 supervoxel_batch 、 supervoxel_union_bbox_crop 、 use_supervoxel_cext 、 use_torch_radiomics 、 torch_gpus 、 torch_gpu_count 、 torch_dtype （torch 键可继承 voxel_level.params ）。

preprocessing_for_subject_level ：受试者级预处理（可选）

  • methods ：预处理方法列表

    • Type ：list

    • Required ：否

    • Default: []

    • Description ：按受试者预处理特征以减少受试者内离群与尺度差。由 PreprocessingMethodFactory 调度，DataFrame 入出（见下文“生境特征预处理实现与扩展”）。

    • Note ： two_step 与 direct_pooling 受试者级不得用删列方法（ variance_filter 、 correlation_filter ），否则拼接后列不一致； two_step 校验拒绝。 one_step 可在受试者级用删列（逐受试者聚类）。

    • 支持的方法与参数 ：

winsorize（winsorization） ：

  • winsor_limits （列表，默认： [0.05, 0.05] ）：下尾和上尾截断分数

  • global_normalize （bool，默认 false ）：跨全部特征全局归一化

minmax（min-max normalization）

  • global_normalize (bool, default: false): global normalization

zscore（Z-score 标准化） ：

  • global_normalize （bool，默认 false ）：全局标准化

robust（robust standardization） ：

  • global_normalize (bool, default: false): global normalization

  • Scales using interquartile range (IQR); robust to outliers

log (log transform) ：

  • global_normalize （布尔值，默认值： false ）：全局变换

  • 处理负值（平移后对数）

variance_filter（低方差过滤） ：

  • variance_threshold （float，默认： 0.0 ）：保留方差高于阈值的特征

  • 注意：丢弃特征列

相关性筛选（高相关性筛选） ：

  • corr_threshold (float, default: 0.95): drop redundant 特征 when the absolute correlation exceeds the threshold

  • corr_method （str，默认 spearman ）： pearson / spearman / kendall

  • 注意：丢弃特征列

  • Examples:

    # Winsorize then normalize
- method: winsorize
  winsor_limits: [0.05, 0.05]
  global_normalize: true
- method: minmax
  global_normalize: true

# Z-score standardization
- method: zscore
  global_normalize: false

group_level的预处理 ：组级预处理（可选）

  • methods ：预处理方法列表

    • Type ：list

    • Required ：否

    • Default: []

    • 说明 ：在队列级预处理特征；常用于离散化以稳定聚类。

    • Applicable modes ：仅 two_step 与 direct_pooling ； one_step 流水线无 group 步——配置的 group 预处理无效。

    • 支持的方法与参数 ：

binning（特征离散化 / 分箱） ：

  • n_bins （int，默认： 10 ）：bin 数

  • bin_strategy （字符串，默认值： uniform ）：分箱策略：

    • uniform ：等宽 bin

    • quantile ：分位数（等频）分箱

    • kmeans ：K均值聚类分箱

  • global_normalize （bool，默认 false ）：跨特征全局分 bin

winsorize（winsorization） ：

  • winsor_limits （列表，默认： [0.05, 0.05] ）：下尾和上尾截断分数

  • global_normalize (bool, default: false): global normalization

minmax / zscore / robust / log ：

  • Same as preprocessing_for_subject_level, applied after group aggregation

variance_filter / correlation_filter（建议在群体级） ：

  • 无监督特征选择的删列；降噪声与冗余

  • variance_filter 参数： variance_threshold

  • correlation_filter 参数： corr_threshold, corr_method

  • 建议：训练时拟合列集；预测时复用相同列

  • Examples:

    # Uniform binning (recommended for habitat analysis)
- method: binning
  n_bins: 10
  bin_strategy: uniform
  global_normalize: false

# Quantile binning (equal frequency)
- method: binning
  n_bins: 20
  bin_strategy: quantile
  global_normalize: false

# Correct

  methods:

# Wrong: duplicate methods key; variance_filter not in list

    - method: winsorize
  methods:
    - method: variance_filter

Recommended pipeline (train → predict reuse)

  • two_step / direct_pooling（训练） ：受试者级 winsorize + minmax （或 zscore ）→ 组级 binning （离散化助聚类）→ 可选 variance_filter / correlation_filter （删列； fit 缓存训练列集）。

  • one_step ：仅配置 preprocessing_for_subject_level ；group 块被忽略。

  • 统一接口 ： Built-in and custom methods implement BaseFeaturePreprocessing, registered via @PreprocessingMethodFactory.register.

  • Execution path ： preprocessing_for_subject_level → 无状态受试者级 apply_stateless_preprocessing ； preprocessing_for_group_level → PreprocessingState.fit/transform （训练缓存 baseline 与逐步 step_states ；预测复用）。

  • 添加方法 ：

    2. Register the method name in habit/schemas/workflows/habitat.py (PreprocessingMethod.method Literal) or rely on schema extension hooks documented in 扩展 HABIT

    3. 若删列，更新 DROPPING_PREPROCESSING_METHODS

    4. 确保模块导入以运行注册装饰器

habitat_segmentation ：生境分割设置

  • 类型 ：object

  • Required ： train 必填； predict 建议（至少 clustering_mode ）

  • Default: null (if fully omitted, Pydantic uses HabitatSegmentationConfig default sub-blocks; see table below)

  • clustering_mode: 聚类 strategy

    • Type ：string

    • Required ：否

    • 默认 ： two_step

    • 允许值 ：

      • two_step: build 超体素 first, then cluster 超体素 into 生境.

supervoxel ：超体素聚类设置

  • Applicable modes ：

    • two_step ：本块配置 逐受试者 体素→超体素聚类（ algorithm 、 n_clusters 等）。

    • one_step ： algorithm 与 one_step_settings 用于 每受试者 体素 → 生境；自动选 k 时覆盖 n_clusters 。

    • direct_pooling ：超体素块不用于聚类（schema 默认可保留）。

  • algorithm ：聚类或分割算法

    • Type ：string

    • 默认 ： kmeans

    • Allowed values (aligned with SupervoxelClusteringConfig):

      • kmeans ：K-means；仅按特征向量聚类—超体素可能在空间上分散。

      • gmm: Gaussian mixture; underlying default covariance_type='full'; SupervoxelClusteringConfig does not expose this field—YAML may ignore it.

      • slic ：SLIC 超像素；联合多通道特征与 3D 坐标得到空间紧凑超体素。 专用参数 （ compactness / sigma / enforce_connectivity 及调参）见下文 habitat_segmentation.supervoxel — SLIC 超像素配置 。

  • n_clusters ：超体素数量（或 SLIC n_segments ）

    • Type ：integer

    • Default: 50

    • Description:

      • two_step ：每受试者固定超体素数；须小于 ROI 体素数。典型 30–100 ；小 ROI 20–30 。

      • one_step 且 fixed_n_clusters 为空：自动 k 搜索上界（见 one_step_settings.max_clusters ），非最终固定值。

  • random_state ：随机 seed

    • 类型 ：整数或 null

    • Default ： null （继承 HabitatAnalysisConfig.random_state ）

  • max_iter ：最大迭代

    • Type ：integer

    • Default: 300

    • 描述 ： kmeans / gmm ：sklearn 最大迭代次数； slic 不同—参见 habitat_segmentation.supervoxel — SLIC 超像素配置 。

  • n_init ：初始化次数

    • Type ：integer

    • Default: 10

    • 说明 ： kmeans / gmm: sklearn n_init; slic: only in one_step auto k—see habitat_segmentation.supervoxel — SLIC 超像素配置.

  • compactness / sigma / enforce_connectivity ：仅 algorithm: slic 时生效—见 habitat_segmentation.supervoxel — SLIC 超像素配置 。

  • one_step_settings ：嵌套一步法自动聚类数（见下文 one_step_settings ）。 不用于 two_step 中逐受试者超体素聚类（两步法始终用固定 n_clusters ）。

  • 完整示例 （K-Means 超体素）：

    supervoxel:
  algorithm: kmeans
  n_clusters: 50
  random_state: 42
  max_iter: 300
  n_init: 10

habitat_segmentation.supervoxel — SLIC 超像素配置#

habitat_segmentation.supervoxel.algorithm: slic 时，habit 在 ROI 内调用 skimage.segmentation.slic ，将 多通道体素特征 （末维为特征通道）与 3D 空间坐标 联合分为 n_clusters 超体素。各向异性 spacing 自动 从掩膜 NIfTI 头读取— 无需 YAML。

Use cases

  • 推荐用于 two_step 阶段 1：超体素空间连贯且局部，不同于纯特征空间 K-Means 超体素。

  • SLIC partitions local anatomical subregions; 队列 生境 are subsequently discovered by 聚类 池化 超体素 特征 vectors.

  • High-dimensional voxel_radiomics 特征 incur much higher compute and memory than raw / mean_voxel_features (builds [Z, Y, X, n_features] 特征 volume in ROI bbox).

YAML path: keys under habitat_segmentation.supervoxel; repo template config/habitat/config_habitat_two_step_supervoxel_slic.yaml.

Parameter reference

  • n_clusters ：目标超体素数（ n_segments ）

    • Default ： 50 （与 supervoxel 块共享）

    • 调参 ：小 ROI 20–30 ；更细纹理 60–100 ；须 小于 ROI 总体素数。

  • compactness ：特征相似与空间紧凑的平衡

    • Type ：float

    • Default: 0.1

    • Description ：传给 skimage.segmentation.slic 。SLIC 前特征通常 winsorize/minmax 归一化，故 0.1 是合理起点（与 RGB 上常见大 compactness 尺度不同）。

    • Tuning:

      • 增大 （ 0.15 – 0.3 ）：更强空间分组、更平滑边界、更少碎片。

      • 减少 (0.05)：更紧密地跟随特征差异；边界跟踪强度/纹理变化，但可能会碎片化。

  • sigma ：SLIC 前高斯平滑宽度

    • Type ：float

    • Default ： 0.0 （无平滑）

    • Description ：分割前在 ROI 内 多通道特征体积 上高斯平滑；单位为 体素 （各向异性时 auto spacing ）。抑制体素/纹理特征高频噪声； 不 替代 preprocessing_for_subject_level 中 winsorize 等。

    • Tuning:

      • 0.0: sharpest boundaries; use when preprocessing is already strong.

      • 0.3 – 0.5 ：轻度去噪； 体素放射组学 可先试（如 0.5 ）。

      • > 1.0 ：可能模糊真实小结构—通常不推荐。

  • enforce_connectivity ：强制空间连通性

    • 类型 ：布尔

    • Default ： true

    • 说明 ： true 时合并孤立小区域以避免“漂浮”超体素；医学 ROI 保持 true 。

  • max_iter ：SLIC 迭代次数

    • Type ：integer

    • Schema default ： 300 （与 kmeans 同字段名； SLIC 勿用 300 ）

    • 推荐 ： 10 （映射到 max_num_iter ）； 15 – 20 可能但收益递减。

  • n_init ：初始化次数

    • Type ：integer

    • Default: 10

    • Description ： 仅 用于 find_optimal_clusters 下 one_step 内嵌 KMeans；对 fit 中 SLIC two_step 无效果 。

  • random_state ：随机 seed

    • 默认: null （继承顶级 random_state ）；建议显式使用 42 以保证可重复性。

one_step_settings ：一步法模式设置（仅 one_step ）

  • min_clusters ：最小聚类数

    • Type ：integer

    • Default: 2

    • Description ：自动选择下界

  • max_clusters ：最大簇数

    • Type ：integer

    • Default: 10

    • 描述 ：自动选择的上限

  • fixed_n_clusters ：固定聚类数

    • Type ：整数或 null

    • 默认 ： null

    • 说明 ：若设置，跳过自动选择并使用该值。

  • selection_method ：自动选择指标

    • Type ：string

    • 默认 ： elbow

    • Allowed values and meaning ：

      • elbow ：惯性曲线膝点，Kneedle 规则检测（默认）

      • silhouette ：轮廓系数（-1 到 1；越接近 1 簇越紧）

      • calinski_harabasz ：Calinski-Harabasz 指数（越高越好）

      • davies_bouldin ：Davies-Bouldin 指数（越低越好）

      • inertia ：簇内平方和（越低 = 越紧密；Kneedle 内部肘部）

      • kneedle ：归一化 inertia 曲线上的 Kneedle（最大偏离点）

      • gap ：gap statistic

      • aic / bic ：信息准则（面向 gmm）

    • 建议 ： elbow （schema 默认）或 silhouette 以便解释

    警告

    v1.0 破坏性变更 ： elbow 与 kneedle 现为同一规则。HABIT elbow 在 k-means inertia 上运行 KneeLocator （曲线 convex、方向 decreasing）— Satopaa, Albrecht, Irwin, and Raghavan（2011， Finding a "Kneedle" in a Haystack ，IEEE ICDCS Workshops）：将 k 与 inertia 归一化到单位正方形，从首点到末点作弦，取离弦最远的 k 。平滑曲线常使 knee 位于人眼拐点右侧。

    聚类文献中， elbow 通常指检查簇内离散度随 k 的变化（Thorndike RL, 1953, Who belongs in the family?, Psychometrika 18(4):267–276）。Thorndike 未 发表二阶差分公式。至 v0.1.x，HABIT elbow 使用 离散曲率肘部 （可视肘部，计算）：inertia 二阶差的 argmax 。这既非 Thorndike 引文，也非今日默认。 elbow 与 kneedle 现均解析为 habit.kernels.cluster_selection.knee_index() ，故 v0.1 写 elbow 的配置仍有效但可能选不同簇数。须复现已发表生境数的研究应设 fixed_n_clusters 为该数。见 构建生境图 与 聚类算法与生境数 。

  • plot_validation_curves ：绘制验证曲线

    • 类型 ：布尔

    • Default ： true

    • 说明 ：绘制指标随簇数变化以解释自动选择

生境 Stage-1 并行与检查点恢复（顶层字段参考）#

These fields sit at the top level of a v0.1 生境 YAML (same level as data_dir). Both train and predict use processes, checkpoint paths, and resume where applicable (predict checkpoints default to <out_dir>/.habitat_predict_checkpoint). CLI: habit get-habitat --resume.

Dual track (v0.1 top-level vs v1 ``policy:``). A native v1 document (version: "1.0") puts the same knobs under a top-level policy: block using RunPolicy field names (workers, subject_timeout_sec, parallel_mode, …). A v0.1 document keeps the individual_* / processes names at the top level; the CLI and run_from_yaml() translate them into policy via LegacyConfigAdapter before building the backend. Full rename table and defaults: Spec、RunPolicy 和 YAML 同构 (RunPolicy YAML mapping) and 执行后端. Annotated v1 example: config/habitat/config_habitat_two_step_v1.yaml.

v1 后端选择（CLI / 配方实况）。 转换后 cmd_habitat / yaml_runner 调用 backend_from_policy() ：

  • backend == "process" → ProcessPoolBackend （进程后端）

  • 或 workers > 1 / processes > 1 → ProcessPoolBackend

  • 或 parallel_mode == "isolated" → ProcessPoolBackend（即使 workers == 1 ）

  • 否则 → SerialBackend

仅 subject_timeout_sec 为正 不会 强制 spawn（库默认 900 ；绑定会抹掉串行路径）。Timeout / OOM / auto_retry_rounds 仅在 ProcessPoolBackend 下生效。

重要

Windows + 进程池： 生成 worker 会重新导入你的脚本。任何会启动 ProcessPoolBackend 的调用（ RunPolicy(backend="process") 、 workers > 1 或 parallel_mode="isolated" ）必须放在以下代码块内:

if __name__ == "__main__":
    ...

Running the same code at module top level (or pasting it into a .py file without this guard) raises RuntimeError: ... bootstrapping phase on Windows. The habit CLI entry point is already safe; this applies to scripts / notebooks converted to scripts / pure-Python recipes. For a quick serial check, use RunPolicy(workers=1, backend="serial") (no spawn).

在 SerialBackend 上，timeout / OOM / parallel_mode / auto_retry_rounds 旋钮不适用。Serial 仍遵守 on_subject_failure 、 resume 、 retry_failed_subjects 、 force_rerun_subjects 、 clear_checkpoint_on_success 。逐受试者 timeout 隔离请设 backend: process （或 parallel_mode: isolated ）。

processes （生境分析顶层）：逐受试者步骤的并行 worker

  • Type ：integer

  • Default ： 2 （须 > 0 ）

  • 说明 ：见上表；与 cap_processes_to_gpu_pool 中 torch_gpus 、 feature_construction.*.params 交互。

cap_processes_to_gpu_pool （生境分析顶层）：将 Stage 1 worker 上限设为 GPU 池大小

  • 类型 ：布尔

  • Default ： false （schema HabitatAnalysisConfig 与 RunPolicy.cap_workers_to_gpu_pool ）

  • 说明 ： When use_torch_radiomics uses CUDA (true or auto with CUDA detected):

    • true ：有效 worker min(processes, len(torch_gpus)) ，每槽一 GPU（ gpu_slot_index ），减少 VRAM 争用；

    • false (default): full processes; workers share GPUs via gpu_slot_index % len(torch_gpus) —good for "single GPU, many CPU" parallel non-GPU steps, but GPU 放射组学 may OOM on same card.

  • Not in config_hash ；恢复时可改。

  • 无效果 于纯 CPU（ use_torch_radiomics: false 或无 CUDA），或 v1 路径选择 SerialBackend 时。

individual_subject_timeout_sec （生境分析顶层）：并行 Stage 1 单受试者墙钟上限

  • 类型 ：float / int（秒）或 null

  • Default ： 900 （15 分钟）；YAML 省略即用默认。

  • 说明 ： On timeout, skip 受试者 (record failure) and continue; null disables per-受试者 timeout. Child processes may still run in background until they exit. v1 path: only applied when ProcessPoolBackend is selected (processes > 1 and translated backend: process); ignored under SerialBackend.

individual_subject_graceful_shutdown_sec （生境分析顶层）：超时后 kill 前的宽限期

  • Type ：float（秒）

  • Default: 15

  • 说明 ： individual_subject_timeout_sec 后父进程调用 terminate() ，等待若干秒后对子进程 kill() 。仅 ProcessPoolBackend（SerialBackend 忽略）。

individual_subject_spawn_timeout_sec （生境分析顶层）：Spawn 阶段墙钟上限

  • 类型 ：float / int（秒）或 null

  • Default: 120

  • Description ：从派发到受试者处理开始的 cap；超时则标记失败并继续—避免父进程在 spawn/import 上永久阻塞。 null = 无 spawn 时限。仅 ProcessPoolBackend（SerialBackend 忽略）。

on_subject_failure （生境分析顶层）：并行逐受试者 Stage 1 失败策略

  • Type ：string

  • Default ： continue

  • 允许值 ：

    • continue ：记录失败受试者；若有成功则继续 Stage 2

    • fail_fast ：首次失败或超时即中止整次运行

Python API 对应：RunPolicy / 执行后端 。软失败模式（几何、批量 fail_fast 、 Cohort.map 聚合）：执行后端上的原子组件 。

oom_backoff （栖息地分析顶层）：在内存错误后减少并行性

  • 类型 ：布尔

  • Default: true (built-in default); repo config/habitat/*.yaml examples often use false—tune for your RAM

  • Description ： true 时，孤立子进程 MemoryError 将待处理受试者 worker 数减 oom_reduce_workers_by （最少 1）。 不处理 原生崩溃（如 Windows 退出 3221225477 / 0xC0000005 ）。仅 ProcessPoolBackend（SerialBackend 忽略）。

oom_reduce_workers_by （生境分析顶层）：每次 OOM 移除的 worker 数

  • Type ：integer

  • Default: 1

  • Description ：仅当 oom_backoff: true 且 ProcessPoolBackend 激活时。

resume （生境分析顶层）：Stage 1 检查点 resume

  • 类型 ：布尔

  • Default ： true

  • Description: When true, reuse checkpointed 受试者 successes. On the v1 CLI/recipe path the store is CheckpointStore under checkpoint_dir (default <out_dir>/.habitat_checkpoint for train, <out_dir>/.habitat_predict_checkpoint for predict); cache keys embed the spec fingerprint. 受试者 recorded as failed are not auto-retried on next resume unless retry_failed_subjects: true or listed in force_rerun_subjects. Within the same ProcessPool run, individual_subject_auto_retry_rounds retries failures by default. Applies to both train and predict.

  • CLI ： habit get-habitat --resume 等价 resume: true 。

  • 另见 ：本页 checkpoint / resume 字段；执行后端 。

strict_checkpoint_hash （生境分析顶层）：检查点 hash 不匹配策略

  • 类型 ：布尔

  • 默认 ： false

  • Description:

    • v0.1 Stage-1 引擎 （遗留）： resume: true 时， true 在 CheckpointConfigHashError manifest.json / config_hash 不匹配时抛 run_mode ； false 警告并丢弃检查点重新运行。仅 Stage-2 哈希迁移的遗留场景仍可能 resume。

    • v1 CLI / recipe 路径 （ cmd_habitat / yaml_runner ）：旧 v0.1 manifest.json / subjects/ 树打开时自动迁移（见下），然后 resume 继续。 strict_checkpoint_hash=True 时磁盘 run_fingerprint.json 与当前 spec 指纹不符或 legacy manifest 损坏/不可读则抛 CompatibilityError 。 strict=False 时指纹不符仅警告且不可达（缓存键亦嵌入指纹）。

  • Not in config_hash ；恢复时可改。

checkpoint_dir （生境分析顶层）：检查点根目录

  • Type ：string 或 null

  • Default ： null （ train → <out_dir>/.habitat_checkpoint ； predict → <out_dir>/.habitat_predict_checkpoint ）

  • 说明 ： Must match previous run for resume; may differ from out_dir when set explicitly.

force_rerun_subjects （生境分析顶层）：强制重跑的受试者 ID

  • Type ：字符串列表

  • Default: []

  • Description ： resume: true 时仍重处理列表内受试者（从 completed/failed 移除并重跑）。

retry_failed_subjects （生境分析顶层）：从检查点重跑全部失败受试者

  • 类型 ：布尔

  • 默认 ： false

  • Description ： resume: true 时将 failed_subjects 中全部 manifest.json 入队 Stage 1 重跑。成功受试者仍跳过，除非也在 force_rerun_subjects 中。

individual_subject_auto_retry_rounds （生境分析顶层）：运行内对失败受试者自动重试轮数

  • Type ：integer

  • Default: 2

  • 说明 ： After first Stage 1 parallel pass, if failed 受试者 remain, rerun up to this many rounds in the same process (failed only). 0 disables. Unlike retry_failed_subjects (next resume only), this applies in the current get-habitat call when ProcessPoolBackend is active. With on_subject_failure: fail_fast, error only after all retry rounds exhausted. Ignored under SerialBackend (processes <= 1 on the v1 path).

individual_subject_parallel_mode （生境分析顶层）：Stage 1 并行执行策略

  • Type ：string

  • Default ： persistent

  • Allowed values ： isolated 、 persistent

  • Description ： persistent （默认）：每个 worker 槽一个长寿命子进程，同次运行内复用（含自动重试轮），摊销 import/spawn。 isolated ：每受试者 spawn（更强隔离；不可 pickle 的 pipeline 或 spawn 调试）。单 GPU persistent 仍串行——主要收益是启动成本。ProcessPoolBackend 选中时用于 train 与 predict 个体级阶段。

    重要

    在 v1 CLI/配方路径上， workers == 1 且 backend: serial 即使 subject_timeout_sec / individual_subject_timeout_sec 为默认 900 也保持进程内。逐受试者 timeout 隔离需要 backend: process 或 parallel_mode: isolated 。

persistent_worker_max_consecutive_failures （生境分析顶层）：持久 worker 重启阈值

  • Type ：integer

  • Default: 1

  • Description ：映射到 RunPolicy.persistent_worker_max_consecutive_failures 。 parallel_mode: persistent 下，连续致命类失败达此次数后重启 worker 槽。

persistent_worker_recycle_after_tasks （生境分析顶层）：周期性持久 worker 回收

  • Type ：integer

  • Default: 0

  • Description ：映射 RunPolicy.persistent_worker_recycle_after_tasks 。 parallel_mode: persistent 下，成功任务达此数后重启 worker（ 0 禁用）。

clear_checkpoint_on_success （生境分析顶层）：train 成功后删除检查点

  • 类型 ：布尔

  • 默认 ： false

  • Description ： true 时在 Stage 1 + Stage 2 全部成功后删除整个检查点目录。

config_hash 与恢复兼容性

  • v1 path ：CheckpointStore 键嵌入 HabitatSpec 指纹，存储写入 run_fingerprint.json 。更改科学旋钮产生新键。 strict_checkpoint_hash: true 时不兼容指纹抛出 CompatibilityError 。可读 v0.1 布局自动迁移（不拒绝）。仅调度旋钮（ processes 、timeouts、OOM 等）在指纹外。

  • v0.1 Stage-1 engine （旧 manifest.json 布局）：

    • In hash （阶段 1 每受试者；变更清检查点）： data_dir 、 feature_construction.voxel_level / preprocessing_for_subject_level / supervoxel_level 、 habitat_segmentation.clustering_mode 、每受试者聚类块（ two_step → supervoxel ； one_step → supervoxel + habitat ）。

    • Not in hash (may resume: true): preprocessing_for_group_level, group habitat.* for two_step/direct_pooling, processes, cap_processes_to_gpu_pool, strict_checkpoint_hash, timeout / OOM / retry / parallel-mode knobs, persistent_worker_*, force_rerun_subjects, out_dir, plot/save switches, etc.

    • manifest.json 还存 individual_config_hash ；仅全哈希的遗留 manifest 在仅 Stage-2 变更时迁移哈希并保留 pkls。

    • resume: true 启动且 hash 不匹配：默认（ strict_checkpoint_hash: false ）警告并删检查点； true 抛 CheckpointConfigHashError 。

Checkpoint directory layout

v0.1 Stage-1 布局（遗留）。v1 CLI/配方路径上这些标记触发自动迁移（migrate_v01_checkpoint_if_needed() ），写入 v1 存储项、将树归档到 .v01_legacy_archive/ 并记录科学上可/不可复用内容:

<checkpoint_dir>/
├── manifest.json      # completed_subjects, failed_subjects, config_hash, individual_config_hash, stage
└── subjects/
    └── {subject_id}.pkl

v1 CheckpointStore 在同一 checkpoint_dir 根下使用逐键文件（见 执行后端 ）。

按 clustering_mode 的 checkpoint 边界

  • two_step / one_step ：在 merge_supervoxel_features （ supervoxel_df ）后保存

  • direct_pooling: saved after individual_preprocessing (体素-level features; larger pkls)

  • Stage 2（combine / concat / group 聚类） 无 checkpoint

save_results_csv ：保存生境结果表

  • 类型 ：布尔

  • Default ： true

  • Description: When true, writes habitats.parquet (default) or habitats.csv per habitats_results_format.

生境_results_format: 生境 results table file format

  • Type ：string

  • Default ： parquet

  • 允许值 ： parquet 、 csv

  • Description: parquet smaller and faster—good for large direct_pooling voxel tables; csv opens in Excel. Output filename is habitats.parquet or habitats.csv.

  • Example:

    save_results_csv: true
habitats_results_format: parquet

random_state （生境分析顶层）

  • Type ：integer

  • Default: 42

on_geometry_mismatch （生境分析顶层，可选）

  • Type ：string

  • 默认 ： resample_mask

  • 允许值 ： resample_mask 、 strict

  • 说明 ：当 ROI 掩膜与参考图像在体素网格元数据（origin / direction / spacing / size）上不一致时，HABIT 默认在 Stage-1 前将掩膜对齐到图像网格：同 shape 数组保留体素并采用图像头；不同 shape 用最近邻重采样。设 strict 则抛 GeometryError （可选）。原生 v1 文档中同一键可在 spec: 下作为 HabitatSpec.on_geometry_mismatch 。

  • Example:

    on_geometry_mismatch: strict

调试 （栖息地分析顶层）

  • 类型 ：布尔

  • 默认 ： false

habitat_pipeline.pkl （训练产物于 <out_dir>/habitat_pipeline.pkl ）

  • Contents ：joblib 序列化的已拟合 HabitatPipeline （group 聚类模型、 PreprocessingState 、config 等）。

  • Auto slimming on save （ HabitatPipeline.save() 调用 prepare_pipeline_for_save ）：

    • Removes training labels_ (prediction needs centers/model params only)

    • Does not write mask_info_cache (NRRD write loads 掩膜 from data_dir on demand via FeatureService.load_mask_info)

    • 不写 _train_checkpoint （检查点仍在 checkpoint_dir ）

  • Size:

    • 不再因 save_images: true 膨胀：掩膜体与 pkl 解耦； direct_pooling 大队列通常 数十至数百 MB （主要随特征维与模型参数而非受试者数）

    • 嵌入 mask_array 的旧 pkls 需 重新训练并保存 以缩小

save_images: Save image outputs from the run (*_habitats.nrrd, etc.)

  • 类型 ：布尔

  • Default ： true

  • Description: Maps to HabitatAnalysisConfig.save_images. When true, train/predict write habitat label maps; masks load from config.data_dir at write time—not stored in habitat_pipeline.pkl. When false, downstream analysis via habitats.parquet / habitats.csv without NRRD output.

verbose ：详细运行日志

  • 类型 ：布尔

  • Default ： true
