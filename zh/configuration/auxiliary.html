辅助工具与数据配置#

数据配置参数#

示例配置文件：

# Control whether to auto-read the first file in a directory
auto_select_first_file: true

images:
  subject1:
    T1: /path/to/subject1/T1/T1.nii.gz
    T2: /path/to/subject1/T2/T2.nii.gz
  subject2:
    T1: /path/to/subject2/T1/T1.nii.gz
    T2: /path/to/subject2/T2/T2.nii.gz

masks:
  subject1:
    T1: /path/to/subject1/T1/mask_T1.nii.gz
  subject2:
    T1: /path/to/subject2/T1/mask_T1.nii.gz

auto_select_first_file ：是否自动读取目录中第一个文件

  • 类型 ：布尔

  • Default ： true

  • Description:

    • true ：自动读取目录中第一个文件（如转换后的 NIfTI 等）。

    • false ：保持目录路径不变（适用于需要整个文件夹的任务，如 dcm2nii）。

images ：图像数据路径

  • 类型 ：字典

  • Required ：yes

  • Default ：无（必填）

  • 说明 ： nested dict; first level is 受试者 ID, second level is image type (key).

masks ：掩膜数据路径

  • 类型 ：字典

  • Required ：否

  • Default ：省略表示无 mask 块

  • Description ：与 images 结构相同。通常用于指定 ROI。

ICC 分析配置（ habit icc ）#

Corresponds to habit.schemas.workflows.icc.ICCConfig. Example: config/auxiliary/config_icc_demo.yaml.

input （必需）

  • type ： files 或 directories

  • file_groups （ type: files ）：二维列表；每组为一 ICC 重复集文件路径；亦接受扁平列表（每项视为单文件组）

  • dir_list （ type: directories ）：目录列表；从各目录收集特征文件

output （required）

  • path ：结果 JSON 输出路径

可选顶层字段

  • metrics ：ICC 指标列表，如 icc1 、 icc2 、 icc3 、 icc1k 、 icc2k 、 icc3k 、 multi_icc 、 cohen_kappa 、 fleiss_kappa 、 krippendorff 等；默认示例 [icc3]

  • selected_features: limit 特征 columns for ICC; null means all

  • full_results （bool，默认 false ）：是否输出完整细节

  • processes （int，可选）：并行进程数

  • debug (bool, default false)

仓库配置模板索引#

场景目录：YAML 配置文件 。 config/ 按功能组织；直接复制修改模板：

Path

Purpose

config/preprocessing/

Image preprocessing and files_preprocessing.yaml subject lists

config/dicom_sort/

仅 DICOM 排序（ sort-dicom ）

config/habitat/

Habitat train/predict (two_step / one_step / direct_pooling) and file_habitat.yaml

config/feature_extraction/

habit extract 生境特征提取

config/radiomics/

Py放射组学 parameters and habit radiomics top-level config

config/auxiliary/

ICC、重复测量与其他辅助分析

配置文件验证#

HABIT 提供配置验证以确保参数正确。

验证规则：

  1. 必需参数检查 ：验证已提供全部必需参数

  2. 类型检查 ：验证参数类型正确

  3. 范围检查 ：验证取值在有效范围内

  4. 依赖检查 ：验证参数依赖是否满足

验证示例：

from habit.schemas.workflows.habitat import FeatureExtractionConfig

# Workflow commands validate YAML via Pydantic models, e.g.:
cfg = FeatureExtractionConfig.model_validate(yaml_dict)

FAQ#

Q1：如何创建配置文件？

A: You can:

  1. 从 config/ 复制示例 YAML（见 YAML 配置文件 ）并编辑路径

  2. 请参阅对应配置页的字段说明

  3. 仅在需要时从零写 YAML（易漏必填字段）

Q2：如何调试配置文件？

A: You can:

  1. debug 模式启用详细日志

  2. 检查 YAML 语法

  3. 逐步添加参数以定位问题

  4. 查看错误信息
