参与贡献#

感谢您对 HABIT 的关注！我们欢迎各种形式的贡献。

如何贡献#

报告 bug#

若发现 bug，请开 GitHub issue：

  1. 搜索已有 issue 避免重复。

  2. 包含清晰标题、复现步骤、期望与实际行为及环境（Python 版本、OS）。

提交代码#

  1. Fork 仓库。

  2. 创建特性分支（ git checkout -b feature/AmazingFeature ）。

  3. 提交更改（ git commit -m 'Add some AmazingFeature' ）。

  4. 推送到分支（ git push origin feature/AmazingFeature ）。

  5. 打开 Pull Request。

代码风格#

  • 遵循 PEP 8。

  • 对 Python 变量、函数参数、模块级名称以及 YAML / Pydantic 配置字段键（例如 out_dir 、 kernel_radius 、 feature_construction ）使用 snake_case 。仅对类使用 PascalCase 。

  • 在合适处添加 docstring。

  • 为新行为添加测试。

  • 确保 pytest tests/ 通过。

约定

描述

类型注解

显式标注函数输入输出，例如 x_train: np.ndarray 。

注释语言

用 英文 写详细代码注释。

图文字

程序化图内生成的全部文字必须为 English 。

工具组织

将共享工具放在 habit/utils/ ，进度条统一使用 habit/utils/progress_utils.py 。

文档#

欢迎贡献文档：

  • 修正笔误并澄清措辞。

  • 添加教程或示例。

  • 保持单一英文文档站点更新。

开发环境搭建#

与终端用户相同，使用 Python 3.10 conda 环境 habit （见 安装 ）:

conda activate habit
pip install -e .
pytest tests/

如何运行测试#

测试在仓库级 tests/ ，由 tests/pytest.ini 配置。两大类：

  1. pytest 单元与 CLI 测试 （ test_*.py ），使用 click.testing.CliRunner 或直接 API 调用。

  2. 可执行演示脚本 ，例如 tests/habitat/habitat_two_step_voxel_radiomics_train.py 。它们使用 config/ 下的演示 YAML，并提供端到端冒烟覆盖。

按 marker 选择测试（marker 定义见 pytest.ini ）：

pytest tests/ -m unit
pytest tests/ -m "habitat and not slow"
pytest tests/ -m cli
pytest tests/test_architecture_contracts.py -m unit

可用 marker： slow / integration / unit / preprocessing / habitat / ml / utils / cli 。

tests/test_architecture_contracts.py 保护注册表与编排器契约。新增工厂或编排器后它 必须通过 。规则本身见 架构 （不变量）。

tests/conftest.py 提供 project_root 、 demo_data_dir 等 fixture；示例数据存放在 demo_data/ 。端到端示例在 tests/integration/ 。

第三方生境插件（注册表与 entry points）见 扩展 HABIT 。新增 CLI 命令或 v0.1 YAML 步骤 schema 为维护者任务；见仓库 developer/sphinx_archive/dev_workflow.rst 。

Pull Request#

提交 PR 前：

  • 全部测试通过。

  • 行为或配置变更时更新文档。

  • PR 描述清楚说明变更。

行为准则#

  • 尊重所有贡献者。

  • 接受建设性反馈。

  • 专注于有助于社区的事情。

感谢贡献！
