Spec、RunPolicy 和 YAML 同构#

Spec / DataSource / RunPolicy 三分法。

habit.spec 持有算法规格（算什么）、运行策略（如何执行）、YAML 同构与旧配置翻译。数据位置刻意缺失：那是 DataSource 契约的事。

用户指南： Python API 指南（v2.0） · 生境指南 示例 。 选择器（生境阶段、参数含义与允许值）： Habitat Spec 组件目录 。名称与参数的实时列表来自各组件构造器（及 Registry.constructor_signature / Registry.create ）——见 插件 introspection API （勿手抄表）。

类#

Spec

一个可插拔组件的规格说明。

Stage

生境数据流中的一个命名步骤。

HabitatSpec

生境分析的完整规格。

MLSpec

表格机器学习分析的完整规格。

RunPolicy

试运行的执行策略。

LegacyConfigAdapter

将冻结的 v0 YAML 映射译为 v1 文档模型。

LegacyTranslation

将 v0 载荷转换为 v1 文档布局的结果。

MigrationReport

一次 migrate_yaml 调用的结果。

函数#

Spec 解析： coerce_spec

将单个组件载荷强制转换为 Spec。

parse_feature_expression

将一个特征树表达式解析为其规范的 Spec 树。

load_habitat_spec

从其 YAML 形式加载 HabitatSpec 。

save_habitat_spec

将 HabitatSpec 写为 YAML。

load_run_policy

从 YAML 映射加载 RunPolicy 。

save_run_policy

将 RunPolicy 写为 YAML。

组装带展开默认值的 native v1 生境文档。

写入完整有效 v1 生境 YAML 供 CLI / YAML-API 重放。

load_habitat_config

加载并结构性验证 v1 栖息地 YAML 文档。

detect_yaml_version

检测 YAML 载荷遵循 v0 还是 v1 布局。

migrate_yaml

将 v0 YAML 配置迁移为 v1 文档布局。

validate_v1_document

验证 v1 文档 payload 的结构。

Stage 与 HabitatSpec.stages （真源）#

生境分析是 有序具名阶段列表 。每个 Stage 将自定义标签与 Spec 组件配对。阶段名是 标签 而非角色关键字：科学角色由位置 + 注册表域推断。推荐标签（仅约定）： extract_voxel_features 、 preprocess1 / preprocess2 / …、 partition 、 extract_supervoxel_features 、 pool 、 fit 、 assign 、 quantify 。正常编写时勿设 role= （仅逃生口）。

战略是 根据阶段顺序推断 的：

Strategy

阶段序列签名

说明

两步法

partition + pool

池化后特征预处理为一等公民

direct_pooling

仅 pool （无 partition）

池化后特征预处理为一等公民

一步法

no pool; partition optional

Per-subject fit on voxels, or on supervoxels when partition is present. Habitat ids are not comparable across subjects.

Partition without pool is one-step on supervoxels. Cohort-level preprocessing still requires pool (validate_dataflow()).

主入口： fit_predict() 。

from habit.spec import HabitatSpec, Spec, Stage
import habit.recipes as recipes

# two_step shape (partition + pool)
two_step = HabitatSpec(
    name="demo_two_step",
    stages=(
        Stage("extract_voxel_features", Spec("raw", {"modalities": ["T1", "T2"]})),
        Stage("partition", Spec("slic", {"n_supervoxels": 50})),
        Stage("pool", Spec("pool")),
        Stage("fit", Spec("kmeans", {"n_habitats": 4})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
        Stage("quantify2", Spec("msi")),
        Stage("quantify3", Spec("ith_score")),
        Stage("quantify4", Spec("non_radiomics")),
        Stage("quantify5", Spec("graph")),
        # Heavy PyRadiomics families (opt-in; require pyradiomics):
        # Stage("quantify6", Spec("traditional")),
        # Stage("quantify7", Spec("whole_habitat")),
        # Stage("quantify8", Spec("each_habitat")),
    ),
    random_seed=42,
)

# direct_pooling shape (pool only; post-pool preprocess allowed)
direct = HabitatSpec(
    name="demo_direct",
    stages=(
        Stage("extract_voxel_features", Spec("raw", {"modalities": ["T1", "T2"]})),
        Stage("preprocess1", Spec("minmax", {"across_features": False})),
        Stage("pool", Spec("pool")),
        Stage(
            "preprocess2",
            Spec(
                "binning",
                {
                    "n_bins": 8,
                    "bin_strategy": "uniform",
                    "across_features": False,
                },
            ),
        ),
        Stage("fit", Spec("kmeans", {"n_habitats": 3})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
    ),
    random_seed=42,
)

# one_step shape (no partition, no pool)
one_step = HabitatSpec(
    name="demo_one_step",
    stages=(
        Stage("extract_voxel_features", Spec("raw", {"modalities": ["T1", "T2"]})),
        Stage("fit", Spec("kmeans", {"n_habitats": 3})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
    ),
    random_seed=42,
)

print(two_step.fingerprint())
print(two_step.describe_methods(style="radiology"))
# result = recipes.Study(spec=two_step).fit_predict(cohort)

命名字段构造函数（已弃用）#

经典命名字段（ voxel_feature_extractor 、 supervoxelizer 、 habitat_model_fitter 、 *_preprocessors 、…）与 pooling 声明在 v3.x 内仍为 弃用构造器 ：它们展开为相同内部阶段列表并保留历史指纹。 HabitatSpec.from_dict 仍可加载命名字段 YAML。新 Python 与新 YAML 应仅声明 stages 。计划在 v4.0.0 移除。

Derived views: a pool stage ⇒ pooling="cohort" / definition_level="cohort"; otherwise "none" / "subject". definition_level is read-only.

生境工厂 two_step_habitat() 、 one_step_habitat() 、 direct_pooling_habitat() 返回 Study ，其 design 在 fit() 前验证名称所承诺的形状。不想手写阶段列表时仍是最短路径。

保存 / 加载与可运行 YAML#

from habit.spec import (
    HabitatSpec,
    RunPolicy,
    Spec,
    Stage,
    load_habitat_spec,
    save_habitat_config,
    save_habitat_spec,
)

spec = HabitatSpec(
    name="two_step",
    stages=(
        Stage("extract_voxel_features", Spec("raw", {"modalities": ["T1", "T2"]})),
        Stage("partition", Spec("slic", {"n_supervoxels": 50})),
        Stage("pool", Spec("pool")),
        Stage("fit", Spec("kmeans", {"n_habitats": 4})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
    ),
    random_seed=42,
)

save_habitat_spec(spec, "habitat_spec.yaml")
restored = load_habitat_spec("habitat_spec.yaml")
payload = spec.to_dict()
again = HabitatSpec.from_dict(payload)

# Runnable v1 document (spec + data + policy + output, defaults expanded).
# Same file works with recipes.run_from_yaml and habit get-habitat --config.
save_habitat_config(
    "habitat_run.yaml",
    spec,
    data_source="demo_data/preprocessed",
    out_dir="out/habitat",
    policy=RunPolicy(workers=1, backend="serial", subject_timeout_sec=None),
)

Fingerprints: pure sugar forms (no explicit stages) keep the historical named-field + pooling payload for two_step / direct_池化 stability. Explicit stages records the ordered list (names + components) and random_seed.

特征树与表达式形式#

可复制配方（单模态叶节点，再组合器）： Habitat Spec 组件目录 第 1 节。嵌套树： 将自定义特征提取器作为插件 。

提取阶段接受 树 状节点：叶节点携带 modality= / modalities= 参数，组合器节点在 params["children"] 下嵌套子节点，载荷为 {"name", "params"} 。任何组件条目可写两种 指纹相同 形式——上述结构化映射，或由 parse_feature_expression() 解析的严格表达式（ coerce_spec() 将字符串交给解析器，映射交给 Spec.from_dict ）：

from habit.spec import HabitatSpec, Spec, Stage, parse_feature_expression

expr = parse_feature_expression(
    'concat(raw("T1"), local_entropy("T2", kernel_size=3))'
)
spec = HabitatSpec(
    name="tree",
    stages=(
        Stage("extract_voxel_features", expr),
        Stage("pool", Spec("pool")),
        Stage("fit", Spec("kmeans", {"n_habitats": 3})),
        Stage("assign", Spec("nearest_centroid")),
        Stage("quantify", Spec("volume")),
    ),
    random_seed=42,
)

# YAML dual form — a string entry is parsed the same way:
again = HabitatSpec.from_dict(
    {
        "name": "tree",
        "stages": [
            {
                "name": "extract_voxel_features",
                "component": 'concat(raw("T1"), local_entropy("T2", kernel_size=3))',
            },
            # ... remaining stages ...
        ],
    }
)

表达式语法刻意严格：模态名为 带引号字符串 ，参数为显式 key=value 字面量，子节点为嵌套调用（子节点中的引号字符串成为隐式 raw 叶）。裸 v0.1 风格标识符会明确报错而非猜测——旧 YAML 适配器对未加引号的 v0.1 表达式仍用宽松解析，仅将加引号表达式路由到此，旧配置字节级一致，新配置得到树。

运行策略 RunPolicy#

RunPolicy is the declarative snapshot of every scheduling concern. Field names match backend keyword arguments so the YAML policy: block and the Python form stay one-to-one.

重要

Windows + 进程池： 生成 worker 会重新导入你的脚本。任何会启动 ProcessPoolBackend 的调用（ RunPolicy(backend="process") 、 workers > 1 或 parallel_mode="isolated" ）必须放在以下代码块内:

if __name__ == "__main__":
    ...

Running the same code at module top level (or pasting it into a .py file without this guard) raises RuntimeError: ... bootstrapping phase on Windows. The habit CLI entry point is already safe; this applies to scripts / notebooks converted to scripts / pure-Python recipes. For a quick serial check, use RunPolicy(workers=1, backend="serial") (no spawn).

from habit.spec import RunPolicy, load_run_policy, save_run_policy

policy = RunPolicy(
    workers=4,
    backend="process",              # "serial" | "process"
    on_subject_failure="continue",  # or "fail_fast"
    subject_timeout_sec=900.0,
    parallel_mode="persistent",     # library default
    auto_retry_rounds=2,
)
save_run_policy(policy, "run_policy.yaml")
policy2 = load_run_policy("run_policy.yaml")

on_subject_failure="continue" 在执行后端内隔离错误。 map() 默认仍抛 ProcessingError ；传 raise_on_failure=False （配方 / CLI）可仅保留成功 — 见 执行后端 与 执行后端上的原子组件 。

用配方运行翻译后的 spec#

v0.1 YAML 通过 habitat_segmentation.clustering_mode 选择生境设计。转换将该旋钮变为命名字段语法加派生的 pooling 声明（ one_step → "none" ； two_step / direct_pooling → "cohort" ）。原生 v1 文档也可显式声明 stages 。无论哪种， fit_predict() 都运行共享阶段执行器。按模式命名的别名仍作为薄验证器保留：

clustering_mode （YAML）

推断的阶段签名 / 语法糖

别名（均派发到 Study.fit_predict ）

two_step

partition + pool（语法糖： pooling="cohort" + supervoxelizer）

two_step_habitat()

one_step

二者皆无（语法糖： pooling="none" ）

one_step_habitat()

direct_pooling

仅池化（语法糖： pooling="cohort" ，无超体素化器）

direct_pooling_habitat()

Pattern: load the YAML, translate with LegacyConfigAdapter, build a HabitatSpec, then call fit_predict():

from pathlib import Path

import yaml
from habit.datasets import make_synthetic_cohort
from habit.spec import HabitatSpec, LegacyConfigAdapter
import habit.recipes as recipes

payload = yaml.safe_load(
    Path("config/habitat/config_habitat_two_step.yaml").read_text(
        encoding="utf-8"
    )
)
translation = LegacyConfigAdapter().translate(payload, "habitat")
spec = HabitatSpec.from_dict(translation.document["spec"])

# Modalities must match the spec's feature expression.
cohort = make_synthetic_cohort(
    n_subjects=4,
    modalities=("pre_contrast", "LAP", "PVP", "delay_3min"),
    rng=42,
)
# cohort = DirectoryDataSource(...).load()  # real data on disk

result = recipes.Study(spec=spec).fit_predict(cohort)
result.save("out/study")
